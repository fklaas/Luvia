# Luvia 13.36.5 / Core 4.36.5 — Memory Deck Spatial, Color & Interaction Correction

## Spatial correction
- Removed the 13.36.4 count-based desktop slot/templates that visually produced a three-column arrangement.
- Desktop cards now use a free full-stage distribution across the available canvas while keeping the protected header area.
- The distribution still re-rolls on reopening, but no longer constrains cards to fixed rows/columns.

## Color source correction
- Added one `resolveMemoryVisualPalette()` path for deck layers, launch stack, open spread, stage accents and focus accents.
- Single-author stack identity is forced to the active trip accent family.
- Trip accent resolution now reads the actual active trip/store/theme fields used elsewhere by Luvia instead of depending on a non-existent `LuviaTripContext.getAccent()` method.
- Multi-author stack layers cycle only through resolved participating profile colors when available; no independent third hue is generated by the Memory UI.
- Current local profile data is merged into Memory member identity for the signed-in traveler before rendering.

## Interaction correction
- Hover now uses a restrained 12 px lift, small scale and rotation settling with a 230 ms easing transition.
- Hovered cards remain above overlapping neighbors while the visible motion itself transitions smoothly.
- Neighboring cards no longer jump apart when one card is hovered.

## Dynamic stage background
- Expanded the decorative memory stage to eight low-contrast travel/memory elements.
- Elements now float slowly at independent durations/delays, with reduced-motion support.
- Atmospheric gradients continue to derive from the trip/profile stage palette.

## Mobile correction
- Mobile no longer uses negative card margins/stack overlap for the open deck.
- It now renders a dedicated readable vertical choreography with alternating horizontal offsets, gentle rotation, real spacing and scrolling.
- Header remains sticky and compact; cards stay fully readable and tappable.
